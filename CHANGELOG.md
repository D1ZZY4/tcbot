# Changelog

All notable changes to this project are documented here. For workflow details, see [`docs/operations/ci-cd.md`](docs/operations/ci-cd.md). For project overview, see [`README.md`](README.md). For contributor rules, see [`CONTRIBUTING.md`](CONTRIBUTING.md). For AI Agents see [`AGENTS.md`](AGENTS.md). For AI agent knowledge see [`docs/README.md`](docs/README.md).

## [Unreleased]

### Added

- **Community rules can be edited, published, and acknowledged from the bot** (`tcbot/modules/rules.py`, `tcbot/modules/helper/pipelines/rules_flow.py`, `tcbot/database/rules_db/`, `docs/features/moderation/rules.md`): staff manage one draft through `/tcrules`, publish it to the main channel as one message per category, and members accept the current version with an `I agree` button on the join greeting. `/rules` is a read-only category menu. Channel messages are edited in place and a failed slot is reconciled by the next publish; there is no separate sync command.
- **Rule publications carry a lock and a reconciliation record** (`alembic/versions/0012_rules_publication.py`, `tcbot/database/rules_db/runs.py`, `tcbot/database/rules_db/publications.py`): a short-lived run prevents two simultaneous publishes, and each channel message slot stores its message id and content hash so an unchanged message is edited rather than reposted.
- **Permission checks by capability** (`tcbot/modules/helper/decorators/auth.py`, `tcbot/database/users_roles.py`): a `permission_only` decorator and the existing `has_permission` helper gate the editor on `rules.manage` without relying on role rank.
- **Community menu links derive from chat ids** (`tcbot/utils/community_links.py`): the Additional menu resolves `MAIN_CHANNEL`, `MAIN_GROUP`, `LOGS`, and `APPEALS` through Telegram, preferring a username over an invite link and omitting a chat that has neither.

### Changed

- **Role vocabulary is now owner, admin, developer, and moderator** (`alembic/versions/0013_role_vocabulary.py`, `tcbot/database/users_roles.py`, `i18n/`): stored founder and tester values are normalised to owner and moderator, and the promotion command no longer accepts the old names. Behavior changes: promotion input and stored role keys use the four final names; the migration is one way.
- **`MAIN_CHANNEL` replaces the static community URL variables** (`tcbot/__init__.py`, `config.env.example`, `README.md`, `AGENTS.md`): `COMMUNITY_CHANNEL_URL`, `COMMUNITY_GROUP_URL`, `COMMUNITY_LOGS_URL`, and `COMMUNITY_APPEAL_URL` are no longer read. Behavior changes: a deployment that relied on those variables must remove them and set the chat ids instead.
- **A reason is required for kicks and mutes** (`tcbot/modules/helper/pipelines/kick_flow.py`, `tcbot/modules/helper/pipelines/mute_flow.py`): both flows now follow the ban and warn flows in asking for a reason without offering Skip. Behavior changes: a kick or mute without a reason now waits for one instead of proceeding.
- **The main group hosts moderation without being connected** (`tcbot/__init__.py`, `tcbot/modules/connect.py`, `tcbot/modules/helper/pipelines/connected_flow.py`): the deployment destinations are recognised as infrastructure and refused by the connect paths, while the configured `MAIN_GROUP` stays a valid federation origin. Behavior changes: a deployment that left `MAIN_GROUP` unset now has to set it to its negative chat id for moderation to work in that group.
- **Unknown `MODULES_NO_LOAD` entries now stop startup** (`tcbot/modules/__init__.py`): a misspelled module name was previously ignored, leaving the module enabled while the operator believed it was disabled. Behavior changes: a typo in `MODULES_NO_LOAD` now fails boot with an explicit error, matching `MODULES_LOAD`.
- **pg_cron jobs run through the scheduled-job registry** (`tcbot/database/pg_cron.py`): the expiry and reconciliation sweeps now use the same dispatcher as their APScheduler counterparts, so they record run and failure telemetry and share the claim-based duplicate guard. Behavior changes: enabling pg_cron no longer reduces failure visibility for those three jobs.

### Fixed

- **A denylisted module outside an allowlist no longer fails startup** (`tcbot/modules/__init__.py`, `tests/test_layering.py`): when both `MODULES_LOAD` and `MODULES_NO_LOAD` were set, denylist names were validated against the already-allowlisted set, so a valid module excluded by the allowlist was reported as a typo and aborted boot. Behavior changes: a valid `MODULES_NO_LOAD` name absent from `MODULES_LOAD` is now a no-op; genuine typos still stop startup.
- **The runner forwards the full documented configuration** (`.github/workflows/run-bot.yml`): `MAIN_CHANNEL` and `PROMOTION_REQUEST_TTL_DAYS` were missing from the runner environment, so rules publication targets and the promotion expiry window silently fell back to defaults despite being set as secrets. Behavior changes: those two secrets now reach the bot on the 24/7 runner.
- **A stale enforcement target can no longer exceed its attempt budget through pg_cron** (`tcbot/database/schema/functions.sql`): the reconciliation sweep released stuck targets with a due retry regardless of how many attempts they had used, so a target that survived three failures could be claimed a fourth time and delivered again. Behavior changes: an exhausted stuck target becomes terminal with no retry deadline, matching the worker-owned recovery path.
- **A dropped clear-all sweep is no longer reported as success** (`tcbot/database/cache/twolevel.py`): when the Redis mutation queue hit its absolute ceiling, a prefix-wide invalidation was discarded silently and skipped its final epoch bump, leaving stale privileges in L2. The failure is now logged and the local window is still closed.
- **A dropped invalidation marker no longer grows without bound** (`tcbot/database/cache/twolevel.py`): when a queued Redis delete was dropped, the local pending-invalidation marker was never released. It is now held only for the L2 lifetime, after which the stale value can no longer be served.
- **Rules screens render in the viewer's locale** (`tcbot/modules/rules.py`, `tcbot/modules/helper/pipelines/reason_flow.py`, `tcbot/modules/helper/pipelines/ban_rules_step.py`): acknowledgement alerts, publish results, and rules-picker prompts forced the English fallback even when translations existed, and the rules help section used a plain rendering mode that could break MarkdownV2 parsing. Behavior changes: those messages follow the resolved locale, and the help section uses the same rendering mode as every other module.
- **Published rule categories keep MarkdownV2 valid** (`tcbot/modules/helper/messages/rules.py`): the item numbering in a category view left the period unescaped, which could make Telegram reject the message. Behavior changes: the published category view renders instead of failing to parse.
- **One incident no longer produces two error reports** (`tcbot/__main__.py`): the asyncio exception handler logged without exception context and then reported the same exception, giving the two records different deduplication fingerprints. Behavior changes: both paths now share one fingerprint, so a single failure ships once.
- **Usernames still resolve while MTProto is unavailable** (`tcbot/modules/helper/extraction/resolve.py`, `tcbot/database/users_cache.py`, `tcbot/database/mtproto.py`): when the Bot API could not resolve an `@username` and the MTProto client was parked, resolution ended there even though the member cache already stored the exact username. An exact, case-insensitive cache lookup is now the last resort while MTProto is down; a live resolver that misses is never overridden by a possibly stale cache entry. Failed lookups are logged with MTProto availability so the degraded state is visible. Behavior changes: `@username` targets resolve during an MTProto outage when the username was observed locally.
- **Rules commands accept every configured prefix** (`tcbot/modules/rules.py`, `tcbot/modules/helper/pipelines/rules_flow.py`, `tcbot/modules/helper/pipelines/ban_rules_step.py`, `tests/test_layering.py`): `/tcrules` and `/rules` were registered with PTB's built-in command handler, which only matches `/`, so `.tcrules` and `!rules` were ignored. The editor conversation also treated prefixed commands as typed input. They now use the project's prefix filters like every other module. Behavior changes: the configured `!` and `.` prefixes now open the rules editor and menu and escape its text steps.
- **Review-card retries respect the Telegram circuit** (`tcbot/notification_worker.py`): a HALF_OPEN breaker now admits one card edit instead of ten concurrent calls, and successes, transport failures, and API refusals update the breaker with the same rules as federation fan-out. Behavior changes: a degraded Telegram recovers with one probe instead of a burst, and the other card edits wait for the next tick.
- **A recovering Telegram circuit no longer burns the federation's retry budget** (`tcbot/enforcement_worker.py`, `tests/test_enforcement_worker.py`): in HALF_OPEN the breaker permits one probe, but the worker still claimed a full batch and recorded every skipped slot as a failed attempt without a delivery. It now claims only the probe and leaves the remaining targets queued. Behavior changes: after an outage the other groups are delivered on the next tick instead of ending terminally undelivered.
- **A failed pg_cron hand-off leaves no stale cron jobs** (`tcbot/database/pg_cron.py`, `tests/test_pg_cron.py`): a partial registration failure removed only the jobs created in that attempt, so entries from an earlier boot could keep running alongside APScheduler. The rollback now removes every job the module owns. Behavior changes: a failed hand-off restores APScheduler as the single owner.
- **Rules text no longer shows doubled escape characters** (`tcbot/modules/helper/messages/rules.py`, `tcbot/utils/time_and_date.py`, `tcbot/modules/helper/pipelines/rules_publish.py`, `tests/test_rules_render.py`): titles, category names, the editor panel, and the publication footer were escaped twice, so punctuation appeared with stray backslashes. Each value is now escaped once by the renderer; a raw timestamp formatter keeps the single source of truth for the date layout.
- **The rules menu acknowledges every button tap** (`tcbot/modules/rules.py`): two read-only category handlers edited the message without answering the callback, leaving a permanent loading spinner. They now answer first.
- **An unknown bot username no longer produces a dead appeal link** (`tcbot/modules/helper/messages/links.py`, `tcbot/modules/helper/keyboards/ban.py`, `tests/test_links.py`, `tests/test_ban_log_kb.py`): the deep-link builder returned a link with an empty host, and the ban log still rendered it as a button. Both now drop the button when the username is unavailable.
- **Webhook updates are no longer lost during shutdown** (`tcbot/alive.py`, `tcbot/__main__.py`, `tests/test_alive_health.py`): the route acknowledged POSTs after the PTB fetcher had stopped, so updates were accepted but never processed. It now returns a retryable response from the moment shutdown begins.
- **Access policies follow the configured schema** (`tcbot/database/schema/policies.sql`): the RLS and view-revocation statements derived the schema from `current_schema()`, unlike every other schema object. They now use the same placeholder as the rest of the schema files, so a connection whose first search-path entry does not exist cannot attach policies to the wrong schema.
- **Member search terms are no longer shipped to the staff error channel** (`tcbot/modules/stats.py`): a failed statistics search logged the raw command text at ERROR level, which is forwarded to `LOGS_ERRORS`. The log now records only the query length.
- **Startup no longer logs deployment chat identifiers** (`tcbot/__main__.py`): a debug line printed the owner and error-log chat IDs, which the configuration loader deliberately keeps out of logs.
- **The rules editor can open a first draft again** (`tcbot/database/rules_db/drafts.py`): the version-number query read an unlabeled column, so a community without a published version raised `KeyError` before any draft could be created. Behavior changes: the first rules draft and publish now work.
- **Rules counts no longer raise on unlabeled result columns** (`tcbot/database/rules_db/items.py`, `tcbot/database/rules_db/categories.py`, `tcbot/database/rules_db/read.py`, `tcbot/database/rules_db/publications.py`): four count queries read a column name SQLAlchemy renumbers, breaking item ordering, empty-category deletion, acknowledgement totals, and channel status counts. Behavior changes: those editor and read surfaces return their values instead of failing.
- **The publish lock no longer targets a nonexistent constraint** (`tcbot/database/rules_db/runs.py`): the single-live-run guard used `ON CONFLICT ON CONSTRAINT` for what is defined as a partial unique index, which PostgreSQL does not match. Behavior changes: acquiring a publish run succeeds and a concurrent publish is refused as intended.
- **A failed replay queue no longer leaves a connected group silently unenforced** (`tcbot/modules/helper/pipelines/connected_flow.py`): the unapplied bans and mutes of a new group are persisted through one queue write. A transient failure is retried briefly, and an exhausted failure now surfaces as a failed connect instead of a confirmation, because the group is already active and a re-add can replay the decisions. Behavior changes: a replay-queue outage now reports a failed connect instead of a blind success.
- **Concurrent ownership transfers can no longer publish a stale owner** (`tcbot/database/users_roles.py`): the post-transfer cache publish was an unconditional write outside the advisory lock, so two overlapping transfers could commit in one order and publish in the other. It now uses the generation-guarded refresh already used by fresh reads, and invalidates the key if that read fails. Behavior changes: none for enforcement, which already reads fresh; display reads converge on the committed owner.
- **Join enforcement no longer mutes or bans the protected Owner** (`tcbot/modules/greeting.py`): ownership can be transferred to a user with an active mute, so that user could later join a connected group and be restricted despite the Owner being a protected target. The join paths now honor the protected-role verdict from the pre-enforcement demote and skip the Telegram action. Behavior changes: a muted user who becomes Owner is no longer restricted or banned when joining a group.
- **A stale enforcement run cannot exceed its attempt budget** (`tcbot/database/enforcement_db.py`, `tcbot/enforcement_worker.py`): a target stranded mid-delivery was released for retry even after using all three attempts, producing an extra Telegram call during an outage. The requeue now makes such a target terminal at the ceiling, and the budget has one owner shared by the worker and the queue. Behavior changes: none; a delivery still gets at most three attempts.
- **The staff roster labels the Owner correctly** (`tcbot/modules/helper/pipelines/stats_flow.py`): the roster still referenced the pre-rename `stats.roster.founder` key, so the heading rendered as a raw key marker and logged a missing-translation error. Behavior changes: the heading now reads "Owner".
- **The warn-limit protection notice uses the current role name** (`tcbot/modules/helper/pipelines/warn_flow.py`): the exemption message shown when a target is promoted mid-flow still said "Founder". Behavior changes: the notice now reads "Owner".
- **Overlapping mute writes no longer extend an expiry from stale state** (`tcbot/database/mutes_db.py`): the active row is now locked and the clock read inside the write, so two simultaneous mute actions cannot compute the same expiry from an outdated row. Behavior changes: none; a single mute is unchanged.
- **Moderation history no longer skips or repeats rows between pages** (`tcbot/database/bans_db/`, `tcbot/database/kicks_db.py`, `tcbot/database/mutes_db.py`): entries that share a timestamp now sort by record id, giving every page a stable order. Behavior changes: none.
- **The proof collection cap holds for every debounce window** (`tcbot/modules/helper/pipelines/ban_flow.py`, `config.env.example`, `docs/getting-started/setup.md`): a short album debounce no longer bypasses the limit on collected proof items. Behavior changes: none.
- **Rank refusals render as readable text** (`tcbot/modules/helper/pipelines/ban_flow.py`, `tcbot/modules/helper/pipelines/mute_flow.py`): refusals that name a role now use plain text, so the viewer sees words instead of raw MarkdownV2 escapes. Behavior changes: the affected refusals are sent without Markdown parsing.
- **Warn auto-bans keep warnings outside the narrowed ban scope** (`tcbot/modules/helper/pipelines/warn_flow.py`, `tcbot/modules/helper/pipelines/demote_flow.py`): the pending-warning slate is no longer cleared for warnings the reduced ban scope leaves untouched. Behavior changes: none.
- **A locale change reaches every cache layer** (`tcbot/database/cache/twolevel.py`): an invalidation marker is now written alongside the removed value, so a stale locale cannot reappear after a change made in another process. Behavior changes: none.
- **A queued revocation can no longer be undone by a local L2 read** (`tcbot/database/cache/twolevel.py`, `tests/test_cache_invalidation_race.py`): a read starting after an invalidation but before its queued Redis delete landed could republish the revoked value from L2 into memory for a whole TTL. The cache now marks locally invalidated keys and reads the source until the delete lands. Behavior changes: a read racing a queued revocation now costs one source read instead of serving the cached value.
- **A cancelled Redis ping no longer leaks a connection pool** (`tcbot/database/redis_client.py`): the temporary pool is released when the startup connectivity check is cancelled. Behavior changes: none.
- **Concurrent error reports cannot corrupt each other** (`tcbot/error_reporter.py`): the deduplication state is now serialised across threads. Behavior changes: none.
- **Fatal startup output is redacted before it is shipped** (`tcbot/__main__.py`, `tcbot/error_reporter.py`): sensitive values are stripped from boot-time errors sent to the error channel. Behavior changes: none.
- **Shutdown drains in-flight bot work before closing the client** (`tcbot/__main__.py`): outstanding tasks finish before the Telegram client is closed, avoiding task errors during stop. Behavior changes: none.
- **Every database engine normalises the provider URL the same way** (`tcbot/database/connection_options.py`, `tcbot/database/engine.py`, `tcbot/database/scheduler/`): the scheduler no longer builds connection options from a differently shaped URL than the application engines. Behavior changes: none.
- **A delayed notification cannot complete another worker's item** (`tcbot/database/notifications_db.py`, `tcbot/notification_worker.py`): completion is now bound to the worker's claim. Behavior changes: none.
- **A decided appeal no longer reopens the ban review slot** (`tcbot/database/bans_db/_writes.py`): the slot is restored only while the appeal is still pending. Behavior changes: none.
- **Group appeals accept ordinary long words** (`tcbot/modules/helper/pipelines/appeal_submit_flow.py`): a message containing a long word is no longer mistaken for a malformed appeal tag. Behavior changes: none.
- **Mute durations parse correctly when the reply target is restated** (`tcbot/modules/helper/extraction/resolve.py`, `tcbot/modules/mute.py`): a repeated target is stripped from the command text before the duration is read. Behavior changes: none.
- **An invalid webhook secret is rejected at startup** (`tcbot/__init__.py`, `config.env.example`, `README.md`, `docs/getting-started/setup.md`): boot now fails with an actionable message instead of failing later during Telegram webhook registration. Behavior changes: an out-of-range or malformed `WEBHOOK_SECRET` now prevents startup.
- **A failed scheduled job keeps its failure record** (`tcbot/database/scheduler/jobs.py`, `tcbot/database/schema/functions.sql`): the record survives the next run so the failure remains visible for diagnosis. Behavior changes: none.
- **Account erasure protects the owner and closes open decisions** (`tcbot/modules/maintenance.py`, `tcbot/database/scheduler/jobs.py`, `alembic/versions/0011_erasure_cleanup.py`): the federation owner cannot be erased and pending decisions are closed when an erasure runs. Behavior changes: none.
- **A role-less user can no longer pass the basic moderator gate** (`tcbot/modules/helper/decorators/auth.py`, `tests/test_authz.py`): the tier was compared against a role name that no longer exists, so a missing role matched the zero rank and was admitted. Behavior changes: the decorator now refuses role-less callers; downstream moderator checks already refused them, so command outcomes are unchanged.
- **Stale role names no longer distort statistics and profile details** (`tcbot/modules/helper/pipelines/stats_flow.py`, `tcbot/modules/helper/pipelines/check_flow.py`, `tcbot/modules/helper/pipelines/demote_flow.py`, `tests/test_stats_roles.py`): owner and moderator keys left over from the vocabulary rename never matched, so moderator counts read zero, the staff-only panes never appeared, and the protected-owner demote check never fired. Behavior changes: moderator counts and staff panes now appear for the correct roles.
- **An incident report is no longer lost when its rollover summary fails** (`tcbot/error_reporter.py`, `tests/test_error_reporter_throttle.py`): a transient failure sending the suppressed-error summary no longer discards the current report that triggered the rollover.
- **Redis queue bound documentation matches the enforced limit** (`tcbot/database/cache/redis_io.py`): the queue comments now state that a revocation is dropped at the hard ceiling when no droppable operation can be evicted, matching the behavior the tests exercise. Behavior changes: none.
- **A stopped integration run no longer breaks the next one** (`tests/postgres_support.py`, `tests/test_schema_helper_recovery.py`): migration schemas are recreated before use instead of being reused with leftover tables and revision stamps from an interrupted run.
- **The expired-warning removal check can run against a real database** (`tests/test_warn_counter_atomicity.py`): the fixture omitted the default actor identity and reused one external reference for two decisions, so the database refused the rows before the behavior under test ran. Behavior changes: none.
- **The promotion-expiry check no longer fights the request lifecycle guard** (`tests/test_promotion_expiry_postgres.py`): the fixture aged a queued request by updating immutable request facts, which the schema trigger refused. It now inserts an already-overdue request directly. Behavior changes: none.
- **Rules editor actions are re-authorized on every tap** (`tcbot/modules/rules.py`, `tcbot/modules/helper/pipelines/rules_flow.py`): category reorder, delete, rename, and draft text edits now re-check the `rules.manage` capability instead of trusting the command that opened the panel. Behavior changes: a user whose capability was revoked can no longer edit rules from an old panel.
- **The rules picker Cancel button works in moderation flows** (`tcbot/modules/helper/pipelines/reason_flow.py`, `tcbot/modules/helper/pipelines/ban_rules_step.py`): the button sent a callback that no handler matched, so tapping it did nothing. Behavior changes: Cancel now aborts the active kick, mute, warn, or ban rules step.
- **A stale button can no longer act on a newer moderation flow** (`tcbot/modules/helper/scope.py`, `tcbot/modules/helper/pipelines/reason_flow.py`, `tcbot/modules/helper/pipelines/ban_confirmation.py`, `tcbot/modules/warns.py`): conversations are keyed per chat and user, so a Cancel, rule picker, or Done button left on an old prompt could cancel, alter, or prematurely execute a newer action by the same moderator. Every moderation callback now records its prompt identity at entry and ignores taps from any other message. Behavior changes: taps on outdated prompts are acknowledged and discarded instead of changing the active action.

### Removed

- **`message_style.py` replaced by `rich.py`** (`tcbot/modules/helper/messages/rich.py`, `tcbot/utils/message_style.py`): the layout pass and the modern rich-message API now have one owner under `helper/messages`. Rich messages are sent through PTB's documented `do_api_request` escape hatch because the pinned PTB release does not wrap `sendRichMessage`; Kurigram offers no equivalent surface. Behavior changes: formatted replies, panel edits, and log posts are sent as rich messages with real headings, lists, and rules instead of literal divider characters, with an automatic MarkdownV2 fallback when the Bot API or client does not support rich messages.
- **Three unused rules-database helpers** (`tcbot/database/rules_db/`): `delete_item`, `get_community_set`, and `set_acknowledgement` had no callers in the application, tests, or scripts, and their re-exports are gone. No externally reachable behavior changes.

### Improved

- **One bounded timeout for Telegram state changes** (`tcbot/utils/transport.py`, `tcbot/enforcement_worker.py`, `tcbot/notification_worker.py`): review-card edits now share the 20-second application-level bound already used by ban, mute, and unban delivery, so a stalled edit cannot hold a worker slot until the transport timeout. Behavior changes: a review-card edit that stalls for more than 20 seconds is retried by the notification worker instead of waiting longer.

### Documentation

- **The appeal reference length matches the handler** (`docs/features/moderation/appeals.md`): the deep link accepts 10 to 32 characters, not exactly 10.
- **The runner no longer forwards removed community URL secrets** (`.github/workflows/run-bot.yml`, `docs/operations/ci-cd.md`): the four `COMMUNITY_*_URL` variables stopped being read when links moved to chat-id resolution, but the workflow and its secret list still named them.
- **Reference signatures match the shipped code** (`docs/features/statistics.md`, `docs/features/roles/promote.md`, `docs/architecture/database.md`): the documented staff-roster, promotion, and warn-query signatures now include their current parameters.
- **The test workflow description lists both Pytest passes** (`README.md`): the serial database pass and the parallel remaining pass are documented separately.
- **Agent rules use the current role names** (`.agents/rules/code-style.md`, `.agents/rules/security-rules.md`): the former Founder and Tester names are replaced with Owner and Moderator in the live rules. Historical release notes are unchanged.
- **Source comments match the shipped role vocabulary** (`tcbot/modules/helper/`, `tcbot/database/`): docstrings and inline comments that still described the former Founder and Tester roles now use Owner and Moderator. The migration array that normalises legacy stored values is unchanged.
- **Guides match the reason requirement and the mute flow** (`docs/features/moderation/`, `docs/reference/keyboard-styles.md`, `docs/features/workflow-overview.md`): the kick and mute guides no longer describe a skippable reason, and the mute executor steps now follow the single decision write, demote, and delivery order used by the code.
- **Reference wording and repository tree are current** (`docs/features/`, `docs/architecture/database.md`, `AGENTS.md`): leftover Owner/Owner and article artifacts are corrected, and the shared message-style utility is listed in the repository tree.
- **Current guides use the shipped role vocabulary** (`README.md`, `AGENTS.md`, `replit.md`, `docs/architecture/helpers.md`): Owner and Moderator replace the former Founder and Tester names in live documentation. Historical release notes are unchanged.
- **Architecture guides describe the new callback guard and cache marker** (`docs/architecture/workflows.md`, `docs/architecture/database.md`): the workflow guide explains stale-tap rejection and the ban confirmation module, and the database guide explains the local pending-invalidation marker.
- **Reference material matches the shipped rules surface** (`README.md`, `AGENTS.md`, `docs/reference/keyboard-styles.md`, `docs/features/moderation/rules.md`, `docs/architecture/helpers.md`, `docs/architecture/database.md`, `docs/architecture/utilities.md`, `docs/features/moderation/connecting.md`): the command table lists `/tcrules` and `/rules`, the repository tree includes the rules, schema, notifications, panels, and metrics modules, the rules-picker callbacks and keyboard ownership are documented, and the permission helper, guarded owner refresh, shared action timeout, and connect replay failure behavior are described.
- **Setup and module guides no longer document removed community URL variables** (`docs/getting-started/setup.md`, `docs/features/misc-modules.md`): the Additional Links menu resolves its buttons from chat ids through Telegram instead of static `COMMUNITY_*_URL` settings with built-in defaults. Historical release notes are unchanged.
