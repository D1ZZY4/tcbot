## [Unreleased]

### Added

- **Rich tables validate their grid** (`tcbot/modules/helper/rich/table.py`, `tests/test_rich_modules.py`): a headerless table no longer emits an empty `<tr></tr>`, spans must be positive, and a grid wider than the Bot API limit of 20 columns is rejected before it can fail the whole message.
- **A table cell can hold a rich button** (`tcbot/modules/helper/rich/table.py`, `rich/button.py`, `tests/test_rich.py`): `table_cell(..., raw=True)` keeps trusted inline markup such as `<tg-button>` verbatim in one cell while every other cell stays escaped. Empty navigation rows are dropped before keyboard conversion, so single-page keyboards stay on the rich path. Behavior changes: none for existing keyboards; paged rules menus no longer fall back to a native keyboard.
- **Rich builders cover every usable Kurigram block and inline entity** (`tcbot/modules/helper/rich/formats.py`, `rich/link.py`, `rich/media.py`, `rich/list.py`, `rich/block.py`): map, audio, document, email, phone, and per-item ordered-list label builders now emit the exact Bot API 10.3 rich HTML. Draft-only thinking blocks and aliases that produce identical markup stay out. Behavior changes: none; existing helpers keep their signatures and output.
- **Translation catalogs are checked for key and placeholder parity** (`tests/test_catalog_parity.py`): every locale must expose the source catalog's keys and placeholders, so a translated template cannot render with a missing argument. Behavior changes: none.
- **The rules editor accepts uploaded Markdown** (`tcbot/modules/helper/pipelines/rules_markdown.py`, `tcbot/modules/helper/pipelines/rules_editor_draft.py`, `tcbot/modules/helper/buttons/rules.py`, `i18n/*/rules.toml`, `i18n/*/button.toml`): staff can upload a `.md` document from the bundled `rules/` format. The document title names the category, each level-two heading becomes an editable item, and bold, italic, inline code, lists, and dividers render as rich blocks. Imported items stay editable with the existing item controls. Behavior changes: a new Upload .md button and a document step in the editor.
- **The rules editor starts at the language picker** (`tcbot/modules/helper/pipelines/rules_editor.py`, `tcbot/modules/helper/buttons/rules.py`, `tcbot/database/rules_db/drafts.py`, `i18n/*/rules.toml`, `i18n/*/button.toml`): `/tcrules` now opens a picker built from the locales that actually have a catalog before the editor menu. The menu offers Back to that picker and Next to continue; the chosen language selects the draft to edit, the version to publish, and the wording readers see. Behavior changes: staff pick a language before authoring and can author a non-default locale from the bot.
- **A short alias for the rules editor** (`tcbot/modules/helper/pipelines/rules_editor.py`): `/tcrls` opens the same staff-only editor as `/tcrules` with every configured command prefix. Behavior changes: a new alias; `/tcr` stays the `/tcrepair` alias.
- **About is now a three-section menu with buttons** (`tcbot/modules/about.py`, `tcbot/modules/helper/messages/panels.py`, `tcbot/modules/helper/buttons/topics.py`, `i18n/*/about.toml`): the About surface from `/start` and its deep link opens an index with Federation, Membership, and Clarification pages, each rendered with the same rich blocks and Back navigation as the Privacy Policy. Wording is summarized from the bundled, version-controlled `about/` documents. Behavior changes: the old single-page About panel is replaced by an index and three section callbacks.
- **Joining a group walks the three membership requirements** (`tcbot/modules/helper/pipelines/connect_added.py`, `tcbot/modules/helper/pipelines/connect_verify.py`, `tcbot/modules/helper/buttons/flows.py`, `tcbot/modules/connect.py`, `i18n/*/connecting.toml`, `docs/flows/connection.md`): the bot-added prompt now shows the three requirements from the membership document, followed by a final confirmation before Connect appears. Every step stays owner-only and a non-owner keeps the shared keyboard live. Behavior changes: the Connect button appears only after all six pages instead of the first prompt, including the moderation-scope page.
- **Rules are grouped by topic with localized labels** (`scripts/seed_rules.py`, `tcbot/modules/helper/messages/rules.py`, `tcbot/modules/helper/buttons/rules.py`, `tcbot/modules/helper/pipelines/rules_picker.py`, `i18n/*/rules.toml`, `docs/features/rules.md`): published rules now use one category per operator document, such as Cheating or Doxing and Privacy, instead of broad buckets. Category labels and descriptions are rule-set data stored per locale in `rule_category_content`, with the stored category title as a fallback, and a category page uses a heading, description, and footer in the same rich style as the Privacy Policy. The moderation picker prefixes a selection with its stored category title.
- **Staff can move between roles without a demote first** (`tcbot/modules/admins.py`, `tcbot/modules/helper/pipelines/promote_steps.py`, `tcbot/database/users_roles.py`, `i18n/*/admins.toml`): `/tcsetrole` opens a picker with only the tiers the executor may grant except the one already held, so Admin to Moderator and Moderator to Developer both work. The Owner can never be targeted, the executor must outrank the current role, and a banned user is refused. The role-change workflow and its callbacks now live in `promote_steps.py` with the promotion logic, and the command is registered with the other role commands in `admins.py`. Behavior changes: a new command and two new callbacks.
- **Catalogs support italic text** (`tcbot/utils/i18n.py`, `i18n/README.md`): alongside `` `code` `` and `*bold*`, templates can use `~italic~` for a short secondary qualifier. The renderer rejects unbalanced, empty, or nested spans exactly as it does for the other two.
- **Rich quotes and highlights can credit an author** (`tcbot/modules/helper/rich/formats.py`, `rich_style.py`): `quote()` and `highlight()` accept an optional author; the blockquote uses the Bot API `<cite>` element and the highlight uses a following credit. New helpers cover pull quotes, footers, anchors, math, time, custom emoji, subscripts, superscripts, and ordered-list markers. Behavior changes: none for existing calls.
- **Local rule documents can seed the community rules feature** (`scripts/seed_rules.py`, `scripts/rules_import.py`, `docs/features/rules.md`): operator Markdown is parsed into plain-text items and published as one new version through the normal draft-to-published flow. The bundled `rules/` documents are the default source, so a fresh checkout can seed without extra files, and `--rules-dir` selects a different folder. Dry run previews the mapping without database writes. The bot reads one content locale, so the seed publishes en-US; no unreadable second locale is written.
- **Community rules can be edited, published, and acknowledged from the bot** (`tcbot/modules/rules.py`, `tcbot/modules/helper/pipelines/rules_editor.py`, `tcbot/database/rules_db/`, `docs/features/rules.md`): staff manage one draft through `/tcrules`, publish it to the main channel as one combined message split only when the UTF-16 budget requires it, and members accept the current version with an `I agree` button on the join greeting. `/rules` is a read-only category menu. Channel messages are edited in place and a failed slot is reconciled by the next publish; there is no separate sync command.
- **Rule publications carry a lock and a reconciliation record** (`alembic/versions/0012_rules_publication.py`, `tcbot/database/rules_db/runs.py`, `tcbot/database/rules_db/publications.py`): a short-lived run prevents two simultaneous publishes, and each channel message slot stores its message id and content hash so an unchanged message is edited rather than reposted.
- **Permission checks by capability** (`tcbot/modules/helper/decorators/auth.py`, `tcbot/database/users_roles.py`): a `permission_only` decorator is available for capability gates, and the editor enforces `rules.manage` through the existing `has_permission` helper without relying on role rank.
- **Community menu links derive from chat ids** (`tcbot/modules/helper/rich/link.py`): the Additional menu resolves `MAIN_CHANNEL`, `MAIN_GROUP`, `LOGS`, and `APPEALS` through Telegram, preferring a username over an invite link and omitting a chat that has neither.

### Changed

- **Health reports whether polling is alive** (`tcbot/alive.py`, `tcbot/__main__.py`): `/health` used to infer liveness from the database and circuit breakers, so a process whose Kurigram loop had stopped could still answer 200 while the keep-alive thread ran. The polling lifecycle now sets a flag owned by the health module around `idle()` and clears it before any shutdown await; the verdict and payload include the new `polling` field. Behavior changes: the endpoint returns 503 during startup and after polling stops.
- **Operator scripts share the production URL helpers** (`scripts/check_schema.py`, `scripts/check_migration.py`, `scripts/print_guard_messages.py`): three copies of the driver-normalising helper and three forwarding wrappers around the schema-scoping helper are replaced with direct imports of `normalize_database_url`, `scoped_url`, and `set_database_url`. Behavior changes: none; credentials still come only from the environment or `config.env`.
- **Rich builders close three markup gaps** (`tcbot/modules/helper/rich/block.py`, `rich/table.py`, `rich/button.py`): a standalone `<a name>` anchor is no longer wrapped in a paragraph, empty table rows are not emitted, and a login-url cell carrying `bot_username` keeps the whole keyboard native instead of silently dropping the field. Behavior changes: none for current builders; these are guards for future callers.
- **Help and stats panels use centered titles and headerless tables** (`tcbot/modules/help.py`, `tcbot/modules/helper/pipelines/stats_panels.py`, `tcbot/modules/helper/rich/block.py`, `tcbot/modules/helper/rich/table.py`, `i18n/*/help.toml`, `i18n/*/stats.toml`): the federation overview no longer shows a Metric/Value column row. It renders a centered bold title from the catalog, an Owner row, a divider, a centered bold Staff title with bold labels and escaped Admin/Developer/Moderator counts, another divider, a centered bold Drill-downs title with bold labels and escaped Users/Bans/Chats counts, and a final divider before the keyboard. Help index, module, and section titles use the same centered construct, and section command tables omit the column header. `blocks()` gains an opt-in `table_header=False` with the previous behavior as the default. Behavior changes: panel layout changes; commands and callbacks are unchanged.
- **The help section panel offers Close beside Back** (`tcbot/modules/helper/buttons/topics.py`, `tcbot/modules/help.py`, `docs/reference/buttons.md`): `back_to_module_btn` accepts `close=True` and composes the existing shared Back and Close row only for help section panels. Other callers keep their Back-only keyboard. Behavior changes: read-only help sections can be dismissed; callbacks are unchanged.
- **The plain-mode template contract is explicit** (`tcbot/utils/i18n.py`): the `t()` documentation now states that plain output still travels inside a rich HTML payload, so callers must escape dynamic values themselves. Behavior changes: none; the rendering behavior is unchanged.
- **Username validation has one owner** (`tcbot/modules/helper/rich/button.py`, `tcbot/utils/i18n.py`): mention buttons and catalog-facing `safe_username()` now share one shape validator instead of two identical patterns, so a future rule change cannot make audit-log links and mention buttons disagree. Behavior changes: none.
- **Rich helpers are split by transport and by block** (`tcbot/modules/helper/rich/`): `msg.py` and `edit.py` are replaced by `send_msg.py`, `reply_msg.py`, and `edit_msg.py`, while payload assembly and block conversion move into the new `block.py`. Transport callers import the owning module directly; the shared names stay available through `messages/` for stable import paths. Behavior changes: none; the public message helpers keep their names and payloads.
- **Proof artifacts are sent as rich slideshows only** (`tcbot/modules/helper/pipelines/proof_post.py`, `tcbot/modules/helper/rich/media.py`, `tcbot/modules/helper/rich/send_msg.py`): evidence now travels in one rich message per media kind per batch of at most 50 files, with each file attached through `InputRichMessageMedia` and referenced by a `tg://photo|video|document` link inside `tg-slideshow`. The plain `send_photo`, `send_video`, `send_animation`, `send_document`, and `send_media_group` path is gone, along with the unused slideshow markup field. Behavior changes: proof appears as one rich slideshow instead of separate media messages; a failed chunk is recorded as partial.
- **Audit logs render their fields as rich tables** (`tcbot/modules/helper/messages/audit_logs.py`): moderation, appeal, role, and group logs now use the same compact two-column Field/Value table as the profile, statistics, and ban-detail panels. Markdown from uploaded documents now renders as rich blocks in the channel and the preview.
