## [Unreleased]

### Removed

- **The unregistered global flood handler is gone** (`tcbot/modules/helper/decorators/ratelimit.py`, `tcbot/modules/helper/decorators/__init__.py`): the universal limiter and its three shared buckets were never attached to the Kurigram dispatcher, so only the decorated per-handler tiers ever throttled updates. The dead handler and its exports are removed. Behavior changes: none; command and callback quotas are unchanged.
- **The separate messages link module is gone** (`tcbot/modules/helper/messages/links.py`, `tcbot/modules/helper/rich/link.py`): URL construction, deep links, and cached community chat links now live with the rich link and mention helpers in one owner. Every import path was updated; no compatibility shim remains. Behavior changes: none; public function names and outputs are unchanged.
- **The webhook transport and its supporting infrastructure are gone** (`tcbot/alive.py`, `tcbot/__main__.py`, `tcbot/__init__.py`, `pyproject.toml`, `uv.lock`, `config.env.example`, `.github/workflows/run-bot.yml`): the Flask server now only serves `/`, `/health` and `/metrics`. The `/webhook` route, webhook registration and shutdown logic, `WEBHOOK_URL` and `WEBHOOK_SECRET` settings, their environment wiring, and webhook-only tests and documentation have been removed. Behavior changes: the bot no longer accepts Telegram updates over HTTP.

### Changed

- **Help builds its topic catalog once per request** (`tcbot/modules/help.py`): the command used to rebuild every module's localized help for the index, the name map, and the topic keyboard. All three now share one build, so opening help and resolving a topic no longer repeat the same imports and rendering. Behavior changes: none; topics, labels, and callbacks are unchanged.
- **Type checking now covers the application, not the legacy test adapter** (`pyrightconfig.json`, `tcbot/`): the suite deliberately rewrites old `(update, ctx)` test calls at runtime, which static analysis cannot model. Application code is type-clean; the test doubles remain covered by pytest instead of by declared types that would hide the adapter boundary. Behavior changes: none.
- **Moderation callbacks fail closed without a live prompt** (`tcbot/modules/helper/scope.py`, `tcbot/modules/helper/pipelines/mod_action_steps.py`, `tests/test_callback_freshness.py`, `tests/test_ban_flush_cleanup.py`): a callback with no recorded prompt identity used to be treated as current, so a fabricated moderation callback could reach an executor with an empty scope. Such taps are now refused. Flow handlers that are flattened into the shared handler group release updates they do not own so another module's text handler still runs. Behavior changes: stale or identity-less moderation buttons no longer execute an action.
- **Kurigram is now the sole Telegram framework** (`tcbot/__main__.py`, `tcbot/modules/helper/context.py`, `tcbot/modules/helper/handlers.py`, `tcbot/modules/helper/messages/`, `tcbot/utils/prefixes.py`): the application lifecycle, update dispatch, command and callback registration, rich-message sending and editing, inline keyboards, and error handling now use native Kurigram APIs. Multi-step flows use an application-owned context with per-chat and per-user state instead of framework-managed conversations. `python-telegram-bot` and its transitive dependencies have been removed from the resolved dependency set. Behavior changes: the bot runs one Kurigram client in long-polling mode; one process per bot token is required.
- **Proof and appeal posting live in their own source modules** (`tcbot/modules/helper/pipelines/proof_post.py`, `appeal_post.py`, `appeal_post_edit.py`, `proof_steps.py`, `appeal_submit.py`): proof upload and appeal review posting are imported directly from their owners instead of being re-exported. Every Kurigram inline-keyboard cell now converts to a rich button in `rich/button.py`; landed proof media is presented through the existing rich slideshow helper. Behavior changes: sends carry rich buttons and proof links render as a slideshow.

### Fixed

- **A sustained error is reported again after each dedupe window** (`tcbot/error_reporter.py`, `tests/test_error_reporter_dedupe.py`): the dedupe map stored the time of the last sighting, so a failure recurring more often than the 30-second window was suppressed forever. It now stores the time of the last report, preserving flood protection while re-reporting an ongoing incident.
- **A failed revocation marker no longer deletes the cached value** (`tcbot/database/cache/twolevel.py`, `tests/test_cache_marker_outcome.py`): the tombstone write and the L2 delete are now one watched operation, so a failed cross-process marker suppresses the delete and keeps the local pending marker. Tombstone failures are counted as Redis outages and the marker now outlives the L2 value. Behavior changes: a Redis failure during revocation no longer leaves a remotely deleted value without a marker.
- **Warn-threshold bans clear warnings in every group as they land** (`tcbot/enforcement_worker.py`, `tcbot/database/enforcement_db.py`, `tests/test_enforcement_worker.py`): deferred or retried groups used to keep at-limit warnings forever because the handler only saw the first delivery report. The enforcement worker now clears warnings per landed chat for automated ban apply runs; manual bans are untouched.
- **A bot re-promotion by an administrator no longer connects the group** (`tcbot/modules/helper/pipelines/connect_added.py`, `tests/test_connect_forum.py`): the bot-added fast path accepted any truthy requester id as authorization. It now re-checks the acting user's live Telegram membership and requires the group owner, failing closed on lookup errors. Behavior changes: the documented owner fast path remains; an administrator's re-promotion no longer replays federation bans and mutes.
- **Ordinary group text no longer triggers editor, search, or permission prompts** (`tcbot/modules/helper/pipelines/rules_editor_draft.py`, `tcbot/modules/stats.py`, `tcbot/modules/helper/pipelines/stats_panels.py`, `tests/test_unowned_text_pass_through.py`): the rules-editor text handler checked permission before confirming that a private editor step was open, so any group message could produce "Use the buttons below..." or a permission refusal. The deferred stats-search handler treated a search flag with no lifetime as ownership and could delete a member's message and re-render a panel long after the prompt was replaced. Editor input now requires a private chat and a pending step, and search input requires a fresh deadline; otherwise both pass the update through. Behavior changes: unowned plain messages are silently ignored instead of posting a group message. A Telegram toast is only available for button taps, so a plain-text notice is not substituted.
- **Ordinary group text no longer creates target-less ban prompts** (`tcbot/modules/helper/pipelines/ban_rules_step.py`, `tcbot/modules/helper/pipelines/proof_steps.py`, `tcbot/modules/helper/pipelines/mod_action_steps.py`, `tcbot/modules/helper/pipelines/ban_actions.py`, `tests/test_moderation_scope_guards.py`): the flatly registered rules-note and reason text handlers accepted any message, then rendered a proof prompt with `ban_target_id` defaulting to `0`, producing cards titled "Banning 0". Those handlers now pass unowned messages through, a rules note requires an explicit note phase, the prompt builder rejects a non-positive target, and a cancelled proof flush is awaited so it cannot clear a newer flow's scope. Behavior changes: stray text in a group no longer starts a ban evidence session; legitimate ban, kick, mute, and warn flows are unchanged.
- **An unknown command no longer ends an appeal session** (`tcbot/modules/helper/pipelines/appeal_submit.py`, `tests/test_moderation_scope_guards.py`): the appeal fallback matched every prefixed command, including `.appeal`, cleared appeal state and replied "Appeal session ended." even when no appeal was active. It now passes such commands to the next flow, so a stale ban proof session can still be cleaned up. Behavior changes: only a live appeal is ended by the fallback; the Cancel button and real commands behave as before.
- **The rules-editor formatting toolbar follows the reader's locale** (`tcbot/modules/helper/buttons/rules.py`, `i18n/en-US/button.toml`, `i18n/id-ID/button.toml`, `tests/test_keyboard_locale_contract.py`, `docs/features/language.md`): six toolbar labels were English literals in Python, so Indonesian readers saw untranslated buttons. The language guide now also lists the supported tilde italic span. Behavior changes: the labels are now localized; callbacks and formatting actions are unchanged.
- **`/tcunban` re-checks the target's role before revoking the ban** (`tcbot/modules/helper/pipelines/unban_actions.py`, `tests/test_unban_flow.py`): the entry-time staff verdict could go stale while the connected-group list loaded. A target promoted or granted a role in that window is now demoted through the fail-closed unban gate first, and an unresolved role read blocks the unban. Behavior changes: a staff holder cannot keep federation rank after a ban is lifted because of a mid-flow promotion.
- **A MTProto lease that cannot be renewed parks its client** (`tcbot/database/mtproto.py`, `tests/test_mtproto_lease.py`): consecutive failed heartbeat refreshes now stop the client and clear its owner instead of logging and continuing until the lease expires. Behavior changes: a database partition long enough for another instance to claim the lease no longer leaves two clients using one Telegram auth key.
- **`/check` no longer repeats a role lookup it never displays** (`tcbot/modules/helper/pipelines/check_panels.py`, `tcbot/modules/helper/identity.py`, `tests/test_check_rich_panel.py`): the recognition note only names special identities, so the profile now resolves those directly instead of classifying the target and reading a fresh role for a note that ignores roles. Behavior changes: none; the same notes render with one less database read.
- **Startup no longer reports success without a live polling client** (`tcbot/__main__.py`, `tests/test_polling_lifecycle.py`): a Kurigram client that disconnects after initialization but before the polling loop now raises instead of returning normally. Behavior changes: a disconnected client produces a failed process rather than an apparently healthy process that receives no updates.
- **A re-ban keeps the group it was filed from** (`tcbot/database/bans_db/_writes.py`, `tests/test_moderation_cases.py`): the new decision records the current origin chat instead of inheriting an empty one from the immutable, superseded row. Behavior changes: re-ban audit entries retain their originating group.
- **Cache revocation markers wait for the Redis mutation to land** (`tcbot/database/cache/twolevel.py`, `tcbot/database/cache/redis_io.py`, `tests/test_cache_marker_outcome.py`): a queued delete or write that cannot reach Redis no longer releases the local pending marker merely because its task finished. Behavior changes: a revoked value stays hidden from promotion into the memory layer until the mutation lands or the Redis TTL expires, and a configured Redis outage is counted as a failed operation even when no command reaches the driver.
- **An erased profile stays erased when later updates arrive** (`tcbot/database/schema/functions/identity.sql`, `triggers.sql`, `functions/maintenance.sql`, `tcbot/database/users_cache.py`, `alembic/versions/0020_erased_identity_guard.py`): identity harvesting used to write the name and username back onto the anonymised row, and a second erasure was refused forever. A database guard now rejects repopulation, the application drops the stale mention entry, and repeat erasures are allowed. Behavior changes: a request against an already-erased account can be filed again to clean up older rows.
- **A revoked MTProto session is rebuilt once instead of boot-looping** (`tcbot/database/mtproto.py`, `tcbot/database/mtproto_store.py`, `tests/test_mtproto_base.py`, `tests/test_mtproto_lease.py`): Telegram can revoke the stored session or invalidate its auth key. Startup now clears only the stale session rows under the owner lease and performs one fresh bot-token login; a duplicate key or bad credentials still fail closed. Behavior changes: deployments with a revoked session recover on the next start instead of restarting repeatedly.
- **Rules publication reconciles one locale at a time** (`tcbot/database/rules_db/publications.py`, `tcbot/modules/helper/pipelines/rules_publish.py`): publishing a draft no longer retires the other content locale's live channel slots, and the unchanged-content check now reads the stored hash before it is overwritten.
- **The typed rules editor accepts the documented URL skip and works from the root menu** (`tcbot/modules/helper/pipelines/rules_editor_draft.py`, `rules_editor_steps.py`, `rules_editor.py`): a single `-` stores no reference URL instead of being rejected, Add Item picks a category deterministically when none is selected, and switching language no longer keeps a category from the previous locale.
- **A landed review-card edit is no longer recorded as failed** (`tcbot/notification_worker.py`, `tests/test_notification_worker.py`): when the settlement write failed after Telegram accepted the edit, the worker reached its attempt ceiling and marked a delivered card as failed. The edit now stays pending for a later settlement instead of being mislabelled.
- **Re-entering `/tcban` no longer archives proof against the first target** (`tcbot/modules/bans.py`, `tcbot/modules/helper/pipelines/ban_actions.py`, `tcbot/modules/helper/pipelines/proof_session.py`, `i18n/*/banning.toml`): a second command during proof collection now retires the unfinished session before replacing the conversation scope, and refuses re-entry while a ban is already executing. Behavior changes: moderator evidence is attributed to the target named by the current command.
- **`/check` escapes a stored username exactly once** (`tcbot/modules/helper/pipelines/check_panels.py`, `tests/test_check_rich_panel.py`): the renderer already escapes placeholders, so a pre-escaped username produced doubled HTML entities. Dynamic usernames with HTML-significant characters now render correctly.
- **The ban Done alert uses the catalog button label** (`i18n/en-US/banning.toml`, `i18n/id-ID/banning.toml`): the alert passed a button label that its template did not declare, so the argument was discarded and the wording was fixed in prose. The label now comes from the single button catalog.
- **Migrations keep the configured schema when libpq options carry another** (`alembic/env.py`): URL or `PGOPTIONS` search paths used to override the configured schema because libpq applies the last option. The configured schema is now emitted last.
- **Category reordering uses the shared database boundary** (`tcbot/database/rules_db/categories.py`): `move_category` opened a raw session outside the circuit breaker and call timeout; it now runs through the same transaction helper as the other category writes.
- **Every send and edit now uses rich buttons only** (`tcbot/modules/helper/rich/msg.py`, `edit.py`, `button.py`): replies and safe edits no longer bypass the button converter, and no inline keyboard is attached as a fallback. Behavior changes: inline keyboards are replaced by `<tg-button-row>` markup in sent and edited messages.
- **Dead MTProto keys keep their operator guidance** (`tcbot/error_reporter.py`): `AuthKeyDuplicated` derives from `RPCError` in Kurigram, so the generic Telegram label used to win over the auth-key label. Behavior changes: duplicate-key incidents are labelled as MTProto auth failures again.
- **Group owners are accepted by `/tcconnect` again** (`tcbot/modules/connect.py`): Kurigram reports the group Creator as `owner`, not `creator`.
- **Proof, unmute, and card retries no longer dereference missing fields** (`tcbot/modules/helper/pipelines/proof_steps.py`, `ban_actions.py`, `warn_actions.py`, `tcbot/enforcement_worker.py`, `tcbot/notification_worker.py`): Kurigram's `Photo` is a single object, `ProofUpload` exposes `message_id`, restoring permissions builds an explicit all-allowed `ChatPermissions`, and the durable card edit passes positional chat and message ids. Behavior changes: photo evidence, expiry restores, and queued review-card retries work instead of raising.

- **Rich replies reach Telegram instead of failing locally** (`tcbot/modules/helper/messages/rich_msg.py`): Kurigram's bound reply already carries the host message's thread id, so replies no longer raise on an unsupported `message_thread_id` argument.
