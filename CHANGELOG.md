## [Unreleased]

### Added

- **Staff can move between roles without a demote first** (`tcbot/modules/admins.py`, `tcbot/modules/helper/pipelines/roles_flow.py`, `tcbot/database/users_roles.py`, `i18n/*/admins.toml`): `/tcsetrole` opens a picker with only the tiers the executor may grant except the one already held, so Admin to Moderator and Moderator to Developer both work. The Owner can never be targeted, the executor must outrank the current role, and a banned user is refused. The role-change workflow and its callbacks now live in the `roles_flow.py` pipeline, and the command is registered with the other role commands in `admins.py`. Behavior changes: a new command and two new callbacks.
- **Catalogs support italic text** (`tcbot/utils/i18n.py`, `i18n/README.md`): alongside `` `code` `` and `*bold*`, templates can use `~italic~` for a short secondary qualifier. The renderer rejects unbalanced, empty, or nested spans exactly as it does for the other two.
- **Rich quotes and highlights can credit an author** (`tcbot/modules/helper/messages/rich_format.py`, `rich_style.py`): `quote()` and `highlight()` accept an optional author; the blockquote uses the Bot API `<cite>` element and the highlight uses a following credit. New helpers cover pull quotes, footers, anchors, math, time, custom emoji, subscripts, superscripts, and ordered-list markers. Behavior changes: none for existing calls.
- **Local rule documents can seed the community rules feature** (`scripts/seed_rules.py`, `scripts/rules_import.py`, `docs/features/rules.md`): operator-local Markdown under `rules/` is parsed into plain-text items and published as one new version through the normal draft-to-published flow. Dry run previews the mapping without database writes, and the source folder stays out of version control. The bot reads one content locale, so the seed publishes en-US; no unreadable second locale is written.
- **Community rules can be edited, published, and acknowledged from the bot** (`tcbot/modules/rules.py`, `tcbot/modules/helper/pipelines/rules_flow.py`, `tcbot/database/rules_db/`, `docs/features/rules.md`): staff manage one draft through `/tcrules`, publish it to the main channel as one message per category, and members accept the current version with an `I agree` button on the join greeting. `/rules` is a read-only category menu. Channel messages are edited in place and a failed slot is reconciled by the next publish; there is no separate sync command.
- **Rule publications carry a lock and a reconciliation record** (`alembic/versions/0012_rules_publication.py`, `tcbot/database/rules_db/runs.py`, `tcbot/database/rules_db/publications.py`): a short-lived run prevents two simultaneous publishes, and each channel message slot stores its message id and content hash so an unchanged message is edited rather than reposted.
- **Permission checks by capability** (`tcbot/modules/helper/decorators/auth.py`, `tcbot/database/users_roles.py`): a `permission_only` decorator is available for capability gates, and the editor enforces `rules.manage` through the existing `has_permission` helper without relying on role rank.
- **Community menu links derive from chat ids** (`tcbot/modules/helper/messages/links.py`): the Additional menu resolves `MAIN_CHANNEL`, `MAIN_GROUP`, `LOGS`, and `APPEALS` through Telegram, preferring a username over an invite link and omitting a chat that has neither.

### Changed

They now render as a heading, divider, quoted purpose, a capability list, a highlighted staff note, and an italic hint, with the same structure in English and Indonesian. Behavior changes: message layout and wording only; commands, deep links, and menu buttons are unchanged.
- **Speed-test results and audit logs are structured rich blocks** (`tcbot/modules/netspeed.py`, `tcbot/modules/helper/messages/audit_logs.py`, `i18n/*/netspeed.toml`): `/st` now shows three compact tables (result, client, server) with headings and dividers instead of an 18-line "Label: value" wall. Missing fields read as Unknown instead of failing the whole result. Audit log fields now render as rich bulleted lists grouped around headings and dividers, so label/value pairs stay readable in a narrow log channel and inline mentions, IDs, and links remain intact. Proof captions stay plain text because proof media is sent with no parse mode, so rich tags are no longer shown literally.

The numbered buttons and the per-user, per-group, per-ban, and per-hit detail cards are gone; navigation keeps only Prev/Next, Search, and Back. The staff roster now starts with a divider like the other panels. Behavior changes: list layout and page size only; access tiers and callbacks for the remaining controls are unchanged.
- **The rules editor guides the reader through each step** (`tcbot/modules/helper/pipelines/rules_flow.py`, `tcbot/modules/helper/buttons/rules.py`, `tcbot/modules/helper/messages/rules.py`, `i18n/*/rules.toml`): the main panel now shows its real item count, a plain next-step hint, and Close without a pointless Back. Publish and Discard appear only once the draft has items. The preview keeps the editor open with Back and Close, and publish guidance explains what to do instead of reporting a failed publish. Behavior changes: the editor panel and preview gain buttons; commands and callbacks are unchanged.
- **The container image keeps its production dependency set** (`Dockerfile`): `uv run` no longer re-adds the development group at verification and startup, so the runtime image ships only production and observability packages.
- **Field labels share one bold style** (`i18n/*/checking.toml`, `stats.toml`, `groups.toml`, `rules.toml`, `greeting.toml`, `banning.toml`, `muting.toml`, `proof.toml`): dense panels now bold their labels consistently in both locales, and a missing-reason qualifier renders in italics. Behavior changes: labels are bold instead of plain; wording, placeholders, and callbacks are unchanged.
- **Help uses headings and a plain quote** (`tcbot/modules/help.py`, `tcbot/utils/i18n.py`, `i18n/*/help.toml`): the index title and module titles are real headings; the index guidance is a plain block quotation without an author. The boilerplate "Federation management bot for" line and the command-prefix note are gone. Each module help ends with a divider before the buttons, and the literal `&lt;module&gt;` is gone. Behavior changes: help layout only; topics and commands are unchanged.
- **The shared Open in PM button keeps a caller-chosen destination** (`tcbot/modules/helper/buttons/menus.py`): `open_pm_btn` is still the one builder for every such button, but accepts the deep-link target instead of hardcoding the start menu. The group and rules surfaces pass `menu`; another entry point can pass its own target.
- **Help entries no longer spell out aliases in prose** (`i18n/*`, `tcbot/modules/helper/messages/rich_text.py`): the `(alias: ...)` notation is gone, so a second code span fills the Alias column of the existing rich command table. The "Note: All commands also work with" line is gone; prefixes are shown as a highlight, and the help index uses a divider and a highlighted instruction. Behavior changes: help layout is denser; commands and aliases are unchanged.
- **Rich edits no longer emit a PTB deprecation warning** (`tcbot/modules/helper/messages/rich_edit.py`): the native `Bot.edit_message_text` method carries the rich payload instead of `do_api_request("editMessageText", ...)`. Buttons now get the same separating rule on edits as on sends.
- **Locale resolution is consistent across keyboards and direct messages** (`tcbot/modules/help.py`, `language.py`, `rules.py`, `greeting.py`, `helper/buttons/`): the help index Close button, language Back button, rules category Back button, promotion decision cards, appeal review buttons, and join-ban DMs follow the reader's locale instead of the default catalog or the group locale. The rules help entry now uses catalog wording and a stable module name.
- **Review-card claims follow the circuit's admission window** (`tcbot/notification_worker.py`): the worker claims no more edits than the circuit can still admit, so a batch that trips the circuit no longer burns retry attempts on edits that never reach Telegram. Behavior changes: fewer cards are claimed while the circuit is degraded; the rest are retried on a later tick.
- **`DB_SCHEMA` accepts only the three project schemas** (`tcbot/__init__.py`, `alembic/env.py`): a misspelled value now falls back to `public` instead of silently creating a fourth schema at startup. Deployment keeps `public`, tests use `test`, and developers use `development`.
- **Stats overview is a table and every keyboard message ends with a rule** (`tcbot/modules/helper/pipelines/stats_flow.py`, `tcbot/modules/helper/messages/rich_msg.py`, `i18n/*/stats.toml`): the federation overview now shows Owner, Staff, Users tracked, Active bans, and Connected chats in a two-column striped table. Rich messages that embed buttons get a divider before the keyboard unless they already end with one, so content never sits flush against the buttons. Behavior changes: the overview is tabular and keyboard messages gain a trailing separator.
- **Cancel buttons are red and page navigation is green** (`tcbot/modules/helper/buttons/`): every Cancel action uses the danger style, while Back, Prev, and Next use success. Behavior changes: color only; callbacks and labels are unchanged.
- **Prompts point down to their buttons** (`i18n/*`): sentences that ask the reader to use a button below now end with the `↴` mark, including start, help, language, privacy, additional links, ban PM, and `/checkme`.
- **Help and menus follow a tighter rich layout** (`tcbot/modules/helper/messages/rich_text.py`, `tcbot/modules/help.py`, `tcbot/modules/helper/buttons/`, `tcbot/modules/privacy.py`, `tcbot/modules/start.py`, `i18n/`): the help section title joins the module and section with `➛` instead of showing a separate line and table caption; command tables use the Alias header for both singular and plural alias markers and no longer show the marker text or its parentheses; every ordinary line becomes its own paragraph so dense panels stay readable. The Back button is green, external-link buttons use `↝`, and read-only stats, help, and privacy menus carry a Close button that deletes the panel message. Privacy pages now use rich headings, lists, and paragraphs. Behavior changes: labels, colors, and panel layout change; callbacks, moderation actions, and wording are unchanged.
- **Button labels carry a shared symbol vocabulary** (`i18n/en-US/button.toml`, `i18n/id-ID/button.toml`, `docs/reference/buttons.md`): navigation uses text arrows and marks (`↤`/`↦` for previous/next, `⤎` for Back, `↧`/`↥` for Details/Simple), while status and channel actions use one pictograph set (`🗸`/`🗶`, `🖈`, `🗩`, `🕬`/`🗪`/`🗫`, `🗟`, `⛁`, `☳`, `☶`). Every supplied symbol is in use and the vocabulary is identical in both locales. Behavior changes: button glyphs and labels change; callbacks, styles, and actions are unchanged.
- **Button colors follow a semantic palette** (`tcbot/modules/helper/buttons/`, `docs/reference/callbacks.md`): blue `PRIMARY` stays the default for actions and navigation, green `SUCCESS` marks positive commits and Back and page navigation, and red `DANGER` marks destructive actions such as Reject and Discard. Behavior changes: the affected buttons change color only; callbacks, labels, and actions are unchanged. Older clients ignore the style field.
- **Long messages use rich dividers and rich lists** (`tcbot/utils/i18n.py`, `tcbot/modules/helper/ban_info.py`, `messages/panels.py`, `messages/rules.py`, `tcbot/modules/help.py`, `i18n/*/help.toml`): the drawn horizontal-rule glyph and arrow bullet markers are gone. Dividers come from `rich_format.divider()` and bullets from `rich_list.bullet_list()`, so panels, ban details, rules views, and help render real `<hr/>` and `<ul><li>` markup. Behavior changes: those messages now use native rich structure instead of drawn characters; wording is unchanged.
- **Join greetings read only the acknowledgement requirement** (`tcbot/modules/greeting.py`, `tcbot/database/rules_db/read.py`): building the I agree button no longer loads every rule item and category on each clean join in the primary group. One indexed statement now returns the published version and its acknowledgement flag. Behavior changes: none; the button and its checks are unchanged.
- **Enforcement claims follow the circuit's admission window** (`tcbot/enforcement_worker.py`, `tcbot/utils/circuit_breaker.py`): deliveries are claimed in bounded chunks sized by the remaining failure headroom, so work that cannot reach Telegram stays queued instead of consuming a retry. Behavior changes: fewer targets are claimed while the circuit is degraded, and the remainder is delivered on a later tick.
- **All user-facing messages ship as rich messages** (`tcbot/modules/helper/messages/rich_msg.py`, `rich_edit.py`, `rich_text.py`, `tcbot/utils/i18n.py`): catalog rendering produces rich HTML, the send and edit transports use the rich Bot API only, and no message is sent with a MarkdownV2, Markdown, or HTML parse mode. MarkdownV2 escaping and conversion modules are gone; keyboard factories render as rich buttons on the rich path and keep their inline representation only where the Bot API cannot express a button.
- **The keyboard package is now `buttons/`** (`tcbot/modules/helper/buttons/`, `docs/reference/callbacks.md`): factories use `_btn` names and the old `keyboards` imports are removed from all callers.
- **Webhook startup preserves updates queued during a rolling restart** (`tcbot/__main__.py`): the shutdown path refuses in-flight POSTs with a retryable response, but boot then discarded those pending updates, so moderation and greeting events were lost between instances. Behavior changes: webhook registration now keeps pending updates, which are safe to redeliver because processing is idempotent. Polling startup still clears stale updates.
- **The Docker image runs as an unprivileged user** (`Dockerfile`): the bot process no longer runs as root inside the container, and the build `PORT` argument now controls the exposed port instead of being ignored. Behavior changes: container filesystem writes are limited to paths owned by the bot user.
- **Role vocabulary is now owner, admin, developer, and moderator** (`alembic/versions/0013_role_vocabulary.py`, `tcbot/database/users_roles.py`, `i18n/`): stored founder and tester values are normalised to owner and moderator, and the promotion command no longer accepts the old names. Behavior changes: promotion input and stored role keys use the four final names; the migration is one way.
- **`MAIN_CHANNEL` replaces the static community URL variables** (`tcbot/__init__.py`, `config.env.example`, `README.md`, `AGENTS.md`): `COMMUNITY_CHANNEL_URL`, `COMMUNITY_GROUP_URL`, `COMMUNITY_LOGS_URL`, and `COMMUNITY_APPEAL_URL` are no longer read. Behavior changes: a deployment that relied on those variables must remove them and set the chat ids instead.
- **A reason is required for kicks and mutes** (`tcbot/modules/helper/pipelines/kick_flow.py`, `tcbot/modules/helper/pipelines/mute_flow.py`): both flows now follow the ban and warn flows in asking for a reason without offering Skip. Behavior changes: a kick or mute without a reason now waits for one instead of proceeding.
- **The main group hosts moderation without being connected** (`tcbot/__init__.py`, `tcbot/modules/connect.py`, `tcbot/modules/helper/pipelines/connected_flow.py`): the deployment destinations are recognised as infrastructure and refused by the connect paths, while the configured `MAIN_GROUP` stays a valid federation origin. Behavior changes: a deployment that left `MAIN_GROUP` unset now has to set it to its negative chat id for moderation to work in that group.
- **Unknown `MODULES_NO_LOAD` entries now stop startup** (`tcbot/modules/__init__.py`): a misspelled module name was previously ignored, leaving the module enabled while the operator believed it was disabled. Behavior changes: a typo in `MODULES_NO_LOAD` now fails boot with an explicit error, matching `MODULES_LOAD`.
- **pg_cron jobs run through the scheduled-job registry** (`tcbot/database/pg_cron.py`): the expiry and reconciliation sweeps now use the same dispatcher as their APScheduler counterparts, so they record run and failure telemetry and share the claim-based duplicate guard. Behavior changes: enabling pg_cron no longer reduces failure visibility for those three jobs.

### Fixed

- **An unknown authorization tier can no longer grant access** (`tcbot/modules/helper/decorators/auth.py`): the minimum-rank gate now resolves through the fail-closed rank helper, so a misspelled tier refuses every caller instead of matching rank zero and admitting everyone.
- **Deployment-owned groups accept commands without a connection row** (`tcbot/modules/helper/guards.py`, `tcbot/modules/language.py`): a group configured as `LOGS`, `LOGS_ERRORS`, `APPEALS`, `PROOFS`, `MAIN_CHANNEL`, or `MAIN_GROUP` was refused by the federation-origin gate with "group not found" even though it is a trusted destination, and its locale could not be set. These groups now pass both checks like the main group. Behavior changes: commands and locale settings work in configured infrastructure groups without connecting them. The bot-add path still refuses to send a connect prompt there, and these chats stay out of the connected-group registry.
- **The language panel keeps its heading, rules, and quote** (`tcbot/modules/language.py`, `i18n/*/language.toml`): the panel was built from newline-separated plain text, so Telegram folded the title, current language, and hint into one line. It now uses a real heading, two dividers, and a block quotation in both locales.
- **`/check` history lists keep their line breaks** (`tcbot/modules/helper/pipelines/check_flow.py`, `tcbot/modules/helper/pipelines/stats_flow.py`, `tcbot/modules/maintenance.py`): the ban, appeal, warn-in-group, kick/mute, search-empty, and repair-list builders returned raw newline-separated text to the rich transport, so Telegram folded the header, status, dates, and reason into one line. Every list now goes through the block converter, so each field renders on its own line.
- **The staff roster renders as separate lines again** (`tcbot/modules/helper/pipelines/stats_flow.py`, `i18n/*/stats.toml`): the panel mixed a divider block with newline-separated bullet lines, so the generic block converter returned the whole fragment verbatim and Telegram folded the role headings and member names into one unreadable run. The roster now builds real paragraph and list blocks, and the catalog leaves bullet markers to the list helper.
- **Date and time are shown as separate values everywhere** (`tcbot/utils/time_and_date.py`, `tcbot/modules/helper/pipelines/stats_flow.py`, `tcbot/modules/helper/messages/audit_logs.py`, `tcbot/modules/helper/ban_info.py`, `tcbot/modules/helper/pipelines/check_flow.py`, `tcbot/modules/helper/pipelines/rules_publish.py`, `i18n/*/stats.toml`, `i18n/*/checking.toml`): timestamps were rendered as one `DD-MM-YYYY | HH:MM` string, so the connected-chats, users, and bans tables, the audit logs, the check panels, and the rules footer mixed the calendar date and clock time into a single cell or line. The tables now carry separate Date and Time columns, log builders emit separate Date and Time fields, and the check and rules templates use distinct date and time placeholders. Behavior changes: those surfaces now show date and time as independent values.
- **Configured chat destinations never join the federation** (`tcbot/database/groups_db.py`, `tcbot/__main__.py`, `tcbot/modules/helper/pipelines/connected_flow.py`, `tcbot/modules/language.py`): the main group was force-registered as an ACTIVE connected chat at every startup and bot re-add, so it appeared in the connected-chat list and count even though the connect paths refused it. The primary group is now anchored with an inactive connection row that keeps its moderation-decision FK target but keeps it out of the federation set; an existing row is never reactivated. The join-decision callback also refuses every configured infrastructure chat. Commands, discussion, appeals, and locale settings still work in the main group, and enforcement still reaches it through the primary merge. Behavior changes: the main group no longer appears as a connected federation chat.
- **The join prompt renders its Connect/Cancel buttons as rich buttons** (`tcbot/modules/helper/pipelines/connected_flow.py`, `tests/test_connect_forum.py`): the prompt was sent with a raw `send_message`, so its styled keyboard stayed a legacy inline keyboard. It now goes through the rich send transport, which converts the cells to rich buttons. Promotion, role-change, appeal, broadcast, speed-test, and cancellation notices were also moved off direct PTB sends/edits onto the rich helpers; staff broadcast text is escaped before the rich transport so it cannot inject markup.
- **Check and stats panels render role and event labels in the reader's locale** (`tcbot/modules/helper/pipelines/check_flow.py`, `stats_flow.py`, `i18n/*/checking.toml`, `i18n/*/stats.toml`): the kick, mute, and staff-roster headings and the missing-actor fallback were hardcoded English even for Indonesian readers. They now come from the catalog in both locales. The rich helper module docstrings were corrected to match the actual transport behavior.
- **`/tcpromote` can change the role of a user who already holds one** (`tcbot/modules/admins.py`, `tcbot/modules/helper/pipelines/roles_flow.py`, `i18n/*/identity.toml`): a command such as `/tcpromote @user moderator` against an existing Admin was stopped by the promote identity refusal, which reported "already an Admin" with circular guidance and never ran the change. The command now classifies a roled target as a role change: a tier the executor may grant is applied, no tier shows the change picker, and a tier the executor cannot grant (Admin for an Admin) stays on the queued-request path. Protected identities are still refused. Behavior changes: promoting a roled target now changes its role or shows the change picker instead of refusing; the Admin refusal now points to `/tcsetrole`.
- **Stats panel headers no longer show literal bold tags** (`tcbot/modules/helper/pipelines/stats_flow.py`): the Users, Connected Chats, User Bans, and Search headers were produced by a catalog template that already renders bold, then bolded a second time, so Telegram displayed `<b>Users</b>` as text above the table. The headers now use the rendered catalog value directly. Behavior changes: those four headers display correctly.
- **Configured Sentry monitoring now starts** (`tcbot/__main__.py`, `tcbot/error_reporter.py`, `tcbot/utils/logger.py`): an unsupported integration option raised during setup and the failure was swallowed, so every deployment with `SENTRY_DSN` ran without error monitoring or event redaction. The numeric event level now comes from the project's Loguru-backed logger instead of the standard logging module. The hook is also typed against the SDK's event shape without making the optional extra a hard dependency. Behavior changes: configured Sentry now receives redacted events.
- **A cache refresh can no longer restore a revoked value** (`tcbot/database/cache/twolevel.py`): an invalidation landing while a critical refresh awaited the Redis tombstone check could republish stale role, connection, group, or owner state into the in-memory layer for the whole TTL. The read now re-checks its generation before publishing.
- **Fresh bans record the group they were filed from** (`tcbot/modules/helper/pipelines/ban_flow.py`): the origin chat id is now stored on a new ban, matching re-bans and warn-threshold bans, so case-rule links keep their audit context. Behavior changes: fresh ban records carry origin attribution.
- **Warn threshold failures are reported with their real error** (`tcbot/modules/helper/pipelines/warn_flow.py`): a failed group read was logged as `NoneType: None` because the exception was a gather value, and a failed post-ban warn clear escaped without handling. Both paths now log the actual failure while keeping enforcement and cancellation behavior unchanged.
- **Throttled updates without a notification surface are blocked** (`tcbot/modules/helper/decorators/ratelimit.py`): an update with neither a message nor a callback query previously ran despite exceeding its quota because the decorator had no branch to return from.
- **Rate-limit replies no longer trip the shared Telegram circuit** (`tcbot/notification_worker.py`): a Telegram service answer such as `RetryAfter` was counted as a transport failure, so five rate-limit replies could stall unrelated federation fan-out and enforcement. Edits now follow the same classification as fan-out.
- **A kick repair with no delivered unban stays failed** (`tcbot/enforcement_worker.py`): an empty reconcile run was recorded as repaired when the circuit opened or no target was claimable, hiding a still-active ban from the unsettled view.
- **A bootstrapped schema is stamped at the head revision** (`tcbot/database/migrations.py`): stamping the base revision replayed a legacy-data import against tables the current schema no longer has and aborted startup. A schema built from the current metadata is now stamped at head.
- **The daily cleanup allows the erasure batch its full budget** (`tcbot/database/scheduler/jobs.py`): the combined daily sweep timed out at 60 seconds while the registry allows 120 seconds for one erasure batch, discarding a valid run.
- **Media helpers keep their captions** (`tcbot/modules/helper/messages/rich_media.py`): `photo()` and `video()` accepted a caption but dropped it from the rendered markup.
- **Block-level rich elements render as blocks** (`tcbot/modules/helper/messages/rich_text.py`): headings, asides, footers, figures, slideshows, and collages are no longer wrapped in a paragraph, which produced invalid HTML.
- **Usernames with a trailing newline are rejected** (`tcbot/utils/i18n.py`): the shape check now uses a full match, so a username cannot carry a newline into an audit-log link.
- **Help examples no longer show a stray ':' in their detail column** (`i18n/{en-US,id-ID}/{admins,disconnecting,kicking,maintenance,muting,warnings}.toml`): 34 example lines used a colon after the command code span, which the rich help table rendered as an orphan mark in the Details cell. All command aliases are also registered in the conversation escape list again, so a typo'd alias is not swallowed by an active flow.
- **Rich help keeps preformatted blocks intact** (`tcbot/modules/helper/messages/rich_text.py`): the appeal-format example was wrapped in `<pre><code>` and then split into paragraphs by the block converter; the preformatted tag is now recognised as a block.
- **Applied-group summaries no longer print a double closing parenthesis** (`tcbot/modules/helper/messages/replies.py`): the failed-group suffix already included the closing bracket in its catalog template, so partial and progress lines ended with `))`.
- **Failed replies and callback notices stay visible** (`tcbot/modules/helper/messages/rich_msg.py`, `rich_edit.py`): send/edit failures are logged at WARNING instead of DEBUG, except for benign gone-chat cases.
- **Commands are no longer swallowed by active conversations** (`tcbot/utils/prefixes.py`, `tcbot/modules/helper/pipelines/{ban_flow,reason_flow,appeal_submit_flow}.py`): a command sent during a flow now reaches its own handler instead of cancelling the flow. Sending `/tcunban` during ban proof collection previously cancelled the ban and left the target banned; only the flow's own re-entry command still ends the pending session.
- **The rules editor stays responsive on every button** (`tcbot/modules/helper/pipelines/rules_flow.py`): Back now works from the discard confirmation instead of leaving a client spinner, and a stale moderation picker Cancel no longer closes an unrelated editor session.
- **A stale rules-picker button cannot cancel a newer ban** (`tcbot/modules/helper/pipelines/ban_rules_step.py`): the picker now records the prompt identity on its first interactive step, so an older Cancel is rejected instead of discarding the live ban.
- **Argument notation renders literally in usage hints** (`tcbot/modules/bans.py`, `disconnecting.py`, `maintenance.py`): `<target>`, `<chat_id>`, `<run_id>`, and `<user_id>` are escaped for the rich HTML transport instead of being treated as tags.
- **A fresh cache read no longer overwrites a cross-process revocation** (`tcbot/database/cache/twolevel.py`): `refresh()` now checks the Redis tombstone as `get_or_fetch()` already did, so a concurrently revoked role or connection cannot be republished for a whole TTL.
- **The rules Open in PM button now opens the rules editor** (`tcbot/modules/rules.py`, `tcbot/modules/helper/pipelines/rules_flow.py`): the group notice used the generic `start=menu` link, so staff landed on the welcome menu and lost their draft context. It now uses `start=tcrules` for the editor and `start=rules` for the public menu, both registered as conversation or command entry points.
- **A cached username can no longer override a reply target during an MTProto outage** (`tcbot/modules/helper/extraction/resolve.py`): a verified override now requires a live resolution, so a reassigned username from the member cache cannot redirect a federation action to the wrong user.

- **Redis queue bound documentation matches the enforced limit** (`tcbot/database/cache/redis_io.py`): the queue comments now state that a revocation is dropped at the hard ceiling when no droppable operation can be evicted, matching the behavior the tests exercise. Behavior changes: none.
- **A stopped integration run no longer breaks the next one** (`tests/postgres_support.py`, `tests/test_schema_helper_recovery.py`): migration schemas are recreated before use instead of being reused with leftover tables and revision stamps from an interrupted run.

- **Rules editor actions are re-authorized on every tap** (`tcbot/modules/rules.py`, `tcbot/modules/helper/pipelines/rules_flow.py`): category reorder, delete, rename, and draft text edits now re-check the `rules.manage` capability instead of trusting the command that opened the panel. - **The rules picker Cancel button works in moderation flows** (`tcbot/modules/helper/pipelines/reason_flow.py`, `tcbot/modules/helper/pipelines/ban_rules_step.py`): the button sent a callback that no handler matched, so tapping it did nothing. - **A stale button can no longer act on a newer moderation flow** (`tcbot/modules/helper/scope.py`, `tcbot/modules/helper/pipelines/reason_flow.py`, `tcbot/modules/helper/pipelines/ban_confirmation.py`, `tcbot/modules/warns.py`): conversations are keyed per chat and user, so a Cancel, rule picker, or Done button left on an old prompt could cancel, alter, or prematurely execute a newer action by the same moderator. Every moderation callback now records its prompt identity at entry and ignores taps from any other message. Behavior changes: taps on outdated prompts are acknowledged and discarded instead of changing the active action.

### Removed

- **The unused DNS dependency** (`pyproject.toml`, `uv.lock`): `dnspython` had no import in the application, tests, or scripts and its stated resolver fallback does not exist. Removing it reduces the runtime dependency surface without changing behavior.
- **MarkdownV2 helper modules** (`tcbot/utils/mdv2.py`, `tcbot/utils/richfmt.py`, `tcbot/modules/helper/messages/rich_mdtwo.py`): rich HTML helpers in `messages/` are the single source of truth. Behavior changes: bot messages no longer use a MarkdownV2 or plain-text fallback send path; the rich Bot API is the only message transport.
- **Three unused rules-database helpers** (`tcbot/database/rules_db/`): `delete_item`, `get_community_set`, and `set_acknowledgement` had no callers in the application, tests, or scripts, and their re-exports are gone. No externally reachable behavior changes.

### Improved

- **Offline migration SQL targets the configured schema** (`alembic/env.py`): generated scripts now pin the search path and place the version table in the configured schema instead of the server default. Behavior changes: `alembic upgrade --sql` emits schema-scoped DDL; applying the full generated script still requires a live connection for schema-object revisions.
- **Pre-commit and the project use the same ruff version** (`.pre-commit-config.yaml`): the hook version now matches the locked toolchain, so lint and format results no longer differ between the hook and CI.
- **One bounded timeout for Telegram state changes** (`tcbot/utils/transport.py`, `tcbot/enforcement_worker.py`, `tcbot/notification_worker.py`): review-card edits now share the 20-second application-level bound already used by ban, mute, and unban delivery, so a stalled edit cannot hold a worker slot until the transport timeout. Behavior changes: a review-card edit that stalls for more than 20 seconds is retried by the notification worker instead of waiting longer.
